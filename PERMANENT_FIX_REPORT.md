## Exact causes and repairs

1. **Reference coverage, not an uncalled estimator.**
   `backend/app/agents/budget_agent.py::BudgetAgent.run` already invoked
   `backend/app/services/cost_estimation_service.py::estimate_missing` (line 146).
   The former ten-row registry covered Japan only. Valid Bengaluru research could
   not match a priced India row; no allowances were supplied. Amadeus credentials
   are absent, and no live hotel pricing adapter exists. Gemini was never an
   acceptable source of verified prices. Added 24 dated historical spending rows
   covering four categories and three spending styles for India and Dubai.
   Independent estimates remain enabled without Amadeus; missing credentials now
   generate a specific, safe diagnostic and budget warning.

2. **Volatile job execution.**
   `backend/app/api/trips.py::create_trip_plan` previously scheduled only an
   in-process FastAPI background task. A stopped process could not recover work;
   status polling eventually marked it failed. New requests now atomically save
   the complete request and a `planning_job` record in the existing `agent_runs`
   table (`trip_planning_service.py::_create_trip`, line 259). No migration or
   production schema change is required.
   `trip_job_service.py::claim` (line 50) uses PostgreSQL `FOR UPDATE SKIP LOCKED`,
   expiring leases, ownership tokens and bounded attempts. `worker.py` renews
   leases, releases owned work on graceful shutdown and cancels processing when
   ownership is lost. Result/failure/checkpoint writes check ownership under the
   trip row lock. Jobs retry provider research; this system performs no bookings.

3. **Earlier stage outputs lost on orchestration exceptions.**
   `travel_graph.py::plan_trip` (line 726) previously received state only when
   `ainvoke` returned. A graph exception/timeout could leave its local result at
   initial state. It now consumes state snapshots and persists completed stages.
   `_persist_result` (line 309) preserves stages not regenerated by a restarting
   worker and preserves itinerary rows until a valid replacement exists.
   `_get_trip` (line 530) does not let a failed revision with no
   result erase an earlier valid agent output. A newly generated complete or
   incomplete budget replaces the old budget as a whole; monetary fields are
   never guessed or merged from unrelated estimates.

4. **Frontend trip selection lost on refresh.**
   `frontend/src/App.tsx` held the selected ID only in React memory; saved journal
   rows could not open their results. It now remembers only a validated ID in
   session storage, reloads status/details from the API and opens history items.
   `TripWorkspace.tsx` rejects mismatched response IDs, ignores responses from an
   old selection and scopes fetch errors to the selected trip. Temporary failures
   retry. Partial plans remain visible, and known budget overruns are displayed
   even when the complete total is unknown. Starting another trip clears the
   selection without claiming to cancel an existing durable job.

5. **API omitted saved research/requirements output.**
   `TripDetailsResponse` now additionally returns `normalized_requirements` and
   `destination_research`. Existing fields remain compatible. Saved
   accommodation/transport, budget, itinerary, review and day rows are retained.
   Structural diagnostics (`core/diagnostics.py::record_state_snapshot`, line 72)
   identify trip, stage, output presence and day count after successful commits;
   exception bodies, request prose, connection strings and keys are not logged.

The working CORS, history routes, request field names, Decimal budget arithmetic,
six-agent architecture and source-price validation were preserved.
